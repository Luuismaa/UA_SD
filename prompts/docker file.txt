Q: puedes explicar como funciona la sintaxis de dockerfile? que tiene y como implementarlo?
Un Dockerfile es un archivo de texto plano que contiene una serie de instrucciones secuenciales que el motor de Docker utiliza para construir una imagen de forma automatizada. Cada instrucción en este archivo añade una "capa" (layer) a la imagen final.

La sintaxis básica sigue el formato estricto de INSTRUCCIÓN argumentos. Por convención, las instrucciones se escriben siempre en MAYÚSCULAS para distinguirlas visualmente de los argumentos o rutas.
Instrucciones Principales

    FROM: Define la imagen base sobre la que construirás. Debe ser obligatoriamente la primera instrucción (ej. FROM openjdk:17-jdk-slim o FROM ubuntu:22.04).

    WORKDIR: Establece el directorio de trabajo interno del contenedor. Si no existe, Docker lo crea. Todas las instrucciones posteriores (RUN, CMD, COPY) se ejecutarán desde esta ruta.

    COPY: Copia archivos o directorios desde tu máquina anfitriona (el proyecto local) hacia el sistema de archivos del contenedor.

    ADD: Funciona igual que COPY, pero con capacidades extra: puede extraer automáticamente archivos comprimidos (.tar.gz) locales o descargar archivos desde una URL remota. Para copias estándar, la buena práctica es usar siempre COPY.

    RUN: Ejecuta comandos en la terminal durante la fase de construcción (build) de la imagen. Se usa para instalar dependencias, compilar código o crear carpetas (ej. RUN apt-get update && apt-get install -y curl).

    ENV: Define variables de entorno que estarán disponibles tanto en la construcción como cuando el contenedor esté en ejecución.

    EXPOSE: Actúa como documentación. Le indica a Docker en qué puerto de red escuchará el contenedor en tiempo de ejecución, aunque no publica el puerto automáticamente.

    CMD: Especifica el comando por defecto que se ejecutará cuando el contenedor se inicie (run). Solo puede haber una instrucción CMD válida por Dockerfile (si pones varias, solo se ejecuta la última).

    ENTRYPOINT: Se utiliza para configurar un contenedor que se ejecutará como un binario estricto. A diferencia de CMD, los parámetros que pases en la consola al hacer docker run no sobrescriben el ENTRYPOINT, sino que se añaden al final de este.

Ejemplo de Implementación (Aplicación Java)

Siguiendo el contexto de tu proyecto en Java, aquí tienes cómo se vería el Dockerfile para empaquetar la Central:
Dockerfile

# 1. Imagen base ligera con Java 17
FROM eclipse-temurin:17-jre-alpine

# 2. Establecer el directorio de trabajo
WORKDIR /app

# 3. Definir una variable de entorno para el puerto
ENV PUERTO_ESCUCHA=8080

# 4. Copiar el código compilado (JAR) desde tu ordenador al contenedor
COPY target/wm-central.jar /app/wm-central.jar

# 5. Exponer el puerto
EXPOSE 8080

# 6. Comando de arranque al levantar el contenedor
CMD ["java", "-jar", "wm-central.jar", "8080", "kafka:9092", "/app/db/central.db"]

(Nota: La sintaxis de corchetes en CMD ["ejecutable", "param1"] se conoce como "forma exec" y es la más recomendada porque envía las señales del sistema operativo directamente al proceso, permitiendo cierres limpios).
Cómo implementarlo y ejecutarlo

    Crear el archivo: En la carpeta raíz de tu proyecto, crea un archivo llamado exactamente Dockerfile (sin ninguna extensión como .txt o .yml).

    Construir la imagen: Abre tu terminal en esa misma carpeta y ejecuta el comando de build. El flag -t te permite ponerle un nombre y una etiqueta (tag), y el punto . final le indica que el Dockerfile está en el directorio actual:
    Bash

    docker build -t wm-central:1.0 .

    Ejecutar el contenedor: Una vez finalizada la construcción, levanta la aplicación mapeando el puerto de tu máquina anfitriona al del contenedor usando -p:
    Bash

    docker run -d -p 8080:8080 --name mi-central wm-central:1.0
